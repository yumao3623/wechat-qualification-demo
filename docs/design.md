# 企业政府资质预评估微信小程序 Demo｜交互与界面设计规格

> 文档版本：Phase 1 / v1.0  
> 规格日期：2026-08-10  
> 当前边界：仅定义页面、组件、状态和交互；不包含正式页面实现。

## 1. 设计目标

1. 在约 1 分钟内让用户理解产品价值并完成关键数据准备。
2. 在任何时点清楚区分“公开/Mock 数据”“用户补充”“系统推导”“需人工核验”。
3. 不用“通过/失败”制造官方认定错觉；突出准备度、缺口和下一步。
4. 登录、协议和个人信息收集保持克制、可预期、可拒绝。
5. Loading / Empty / Error / Success 均有明确布局、文案和下一步操作。

## 2. UI 方向

- 风格：可信、克制、轻量；避免政府官方视觉仿冒、奖章式“认证通过”和夸张动效。
- 主色：深蓝/青色用于导航和主 CTA；橙色用于“需补充/人工核验”；红色仅用于明确风险或错误。
- 卡片：白底、弱阴影/细边框，圆角适中。重点数字配单位和统计期。
- 状态色不能作为唯一信息载体，必须同时有文字和图标。
- 全局固定提示：“本工具仅提供预评估，最终以主管部门政策、申报通知及审核结果为准。”
- Mock 模式在搜索、画像和报告持续显示“虚构 Demo 数据”标签。

## 3. 导航与页面层级

```text
Tab：首页
  └─ 企业搜索
      └─ 主体确认
          └─ 企业画像
              └─ 补充经营数据（按需）
                  └─ 协议弹窗
                      └─ 诊断进度
                          └─ 报告详情
                              ├─ 证据链
                              ├─ 缺口与行动
                              └─ 联系顾问

Tab：报告
  ├─ 用户主动登录
  ├─ 诊断进度
  └─ 报告详情

Tab：我的
  ├─ 使用说明
  ├─ 隐私政策
  ├─ 用户协议
  ├─ 免责声明
  └─ 退出登录（仅已登录）
```

路由只传企业/诊断/报告 ID，不携带完整对象。页面 `onShow` 需要恢复诊断和 Session 状态。

## 4. 全局组件

| 组件 | 用途 | 关键规则 |
| --- | --- | --- |
| `AsyncState` | Loading/Empty/Error/Success 容器 | 错误只显示用户可理解文案和 trace ID，不显示堆栈 |
| `DemoBadge` | 标识虚构数据 | 任何 Mock 企业相关页面必须可见 |
| `SourceBadge` | 数据来源 | `demo_mock/provider/user/derived/official_platform` 分色并显示观察时间 |
| `PeriodValue` | 数值、单位、统计期 | 统计期无效时用警示态，不参与判断 |
| `QualificationCard` | 四类资质摘要 | 状态、摘要、主要缺口、人工核验数量、查看详情 |
| `CriterionRow` | 单项证据 | 条件、要求、实际值、来源、结果、说明、行动 |
| `AgreementDialog` | 三份法律文档同意 | 每次 `open()` 都重置 `checked=false` |
| `FieldRenderer` | 动态表单控件 | 由服务端 schema 驱动；支持数值、选择、布尔、日期、列表 |
| `GapActionCard` | 缺口与行动 | 优先级、影响、动作、证据引用、顾问建议 |
| `InlineNotice` | 免责声明/隐私/口径提示 | 不遮挡主要操作，不暗示官方背书 |

## 5. 状态和文案规范

### 5.1 资质状态

| API 状态 | 展示文案 | 视觉 | 使用限制 |
| --- | --- | --- | --- |
| `promising` | 较有希望 | 青绿 | 必须仍显示人工核验项和免责声明 |
| `opportunity` | 存在机会 | 蓝 | 强调尚需准备/核验 |
| `needs_data` | 需补充数据 | 橙 | CTA 指向缺失字段 |
| `not_met` | 暂不满足 | 红棕 | 展示明确缺口与可行动建议 |
| `not_applicable` | 不适用 | 灰 | 说明地域/主体/版本原因 |

禁止出现“保证通过”“一定符合”“已获得资质”“官方认定通过”“保证获得补贴”。

### 5.2 通用四态

- **Loading**：骨架或进度提示；禁用重复提交；超过合理时长显示“仍在处理中”。
- **Empty**：说明为什么为空，并提供单一主行动；空态不是错误。
- **Error**：说明影响、是否保存、可执行的重试/返回；内部信息隐藏。
- **Success**：展示完成结果与下一步；提交成功不夸大后台处理状态。

## 6. 页面总表：登录边界与四态

| 页面 | 登录 | Loading | Empty | Error | Success |
| --- | --- | --- | --- | --- | --- |
| 首页 | 游客 | 可选内容骨架 | 不适用（静态核心内容必须存在） | 配置失败仍显示基本 CTA/免责声明 | 价值卡、四类介绍、开始 CTA |
| 企业搜索 | 游客 | “正在搜索 Demo 企业”+禁用按钮 | “未找到匹配的虚构 Demo 企业”+改关键词 | 请求失败+重试 | 结果列表+Demo 标签 |
| 主体确认 | 游客 | 详情骨架 | ID 不存在按 Error | “企业信息不可用”+返回搜索 | 关键主体字段+确认/重选 |
| 企业画像 | 游客 | 分区骨架 | 无画像字段时提示并允许返回 | 获取失败+重试 | 已获取/缺失/待补充分区 |
| 补充数据 | 游客 | schema 骨架 | “当前无必填补充项”+继续 | schema/校验失败 | 有效保存+来源标记 |
| 协议弹窗 | 游客 | 登录/创建中 | 不适用 | 登录或创建失败+重试/关闭 | 创建成功进入进度 |
| 诊断进度 | 已登录 | 分阶段进度 | ID 不存在按 Error | failed 或请求失败+重试/返回 | ready 后进入报告 |
| 报告详情 | 已登录 | 报告骨架 | 尚未 ready 显示进度入口 | 无权限/生成失败 | 四类结果+证据/行动入口 |
| 证据链 | 已登录 | 列表骨架 | 无证据属数据错误并提示 | 加载失败+重试 | criterion 分组列表 |
| 缺口与行动 | 已登录 | 列表骨架 | “当前未发现明确缺口，仍需人工复核” | 加载失败 | gap/action 列表 |
| 报告 Tab | 保存数据需登录 | 查询列表 | 已登录无报告 | 请求失败/诊断失败 | 进行中卡或报告列表 |
| 我的 Tab | 游客 | Session 检查不阻塞法律入口 | 不适用 | Session 失败按游客展示 | 法律入口；条件退出 |
| 联系顾问 | 游客 | 提交中 | 不适用 | 字段/网络错误 | “咨询需求已提交” |
| 法律/帮助 | 游客 | 文本骨架 | 内容缺失按 Error | 加载失败 | 标题、版本、生效日、正文 |
| Admin | 本地限制 | 表格骨架 | 无诊断/无线索 | API 错误 | 只读表格 |

## 7. 首页 Tab

### 7.1 布局

1. 顶部品牌区：产品名称 + “资质预评估 Demo”。
2. Hero：标题“约 1 分钟了解企业申报准备度”；副标题强调非官方认定。
3. 主 CTA：“开始预评估”。
4. 四类资质卡：高新技术企业、科技型中小企业、专精特新、杭州新雏鹰区域示例。
5. 三步说明：选企业 → 补关键数据 → 看证据与行动。
6. 数据与隐私说明：先体验，不自动登录，不强制手机号。
7. 固定免责声明。

### 7.2 交互

- 点击主 CTA 直接进入企业搜索，不登录、不弹协议。
- 点击资质卡只展开简要说明/适用地域，不请求企业数据。
- 进入或切回首页不得触发 `wx.login`、手机号或协议弹窗。

## 8. 企业搜索

### 8.1 布局

- 步骤条：Step 1/4 选择企业。
- 搜索框：提示“输入虚构 Demo 企业名称关键词”。
- 搜索按钮；空输入时禁用或给字段提示。
- 结果卡：企业名称、Demo 编号、地区、行业、经营状态、Demo 标签。
- 底部说明：不展示真实企查查数据。

### 8.2 交互

- 2–50 字符，去首尾空格；回车/按钮触发搜索。
- 新搜索取消或忽略旧请求结果，避免竞态覆盖。
- 点击结果进入主体确认；不得直接创建诊断。

## 9. 主体确认

### 9.1 布局

- 步骤条仍为 Step 1/4。
- 标题“请确认企业主体”。
- 字段：名称、Demo 编号、法定代表人、成立日期、注册资本、地区、状态、行业。
- 主按钮“确认该企业”；次按钮“返回重新搜索”。

### 9.2 交互

- 确认后创建/更新本地草稿上下文并进入画像。
- 返回重选清除旧企业的补充值和 schema；不得串用企业数据。

## 10. 企业画像

### 10.1 布局

- Step 2/4。
- 顶部企业摘要 + Demo 标签。
- 三组可折叠卡：
  - 已获取：展示值、单位、期间、来源。
  - 缺失：只说明缺失事实。
  - 需要补充/核验：说明被哪些资质使用及敏感性。
- 底部 CTA：有动态字段时“补充关键数据”；无动态字段时“准备发起诊断”。

### 10.2 交互

- `manual_evidence_required` 不伪装为普通必填数值，展示“后续需人工核验”。
- 点击来源可查看来源类型、观察时间和置信说明。

## 11. 动态补充经营数据

### 11.1 布局

- Step 3/4。
- 顶部说明“仅询问当前判断缺少的数据”。
- 按“基础规模 / 人员研发 / 收入财务 / 知识产权与资质 / 市场融资”分组；空组不渲染。
- 每个字段显示标签、单位、统计期、用途（影响哪些资质）、口径帮助和敏感提示。
- 底部保存与继续；可返回画像。

### 11.2 控件规则

- 数值字段使用合适数字键盘，允许 `0`，拒绝负数（确有负数语义的字段另行定义）。
- 比例不直接要求用户重复填写：优先收集分子/分母并由系统推导。
- 布尔值用明确的“是 / 否 / 不清楚”，不把未选择当“否”。
- 列表字段支持逐项添加知识产权、融资或奖项；每项带状态和证据来源。
- 保存时进行字段级校验；统计期冲突就地说明，不清空其他输入。
- 用户补充后重新请求 missing-fields；真正减少字段并影响后续结果。

## 12. 协议弹窗与登录

### 12.1 布局

- 标题“发起诊断前请阅读”。
- 简短说明将处理的企业数据、报告保存和 Demo Auth 性质。
- 三个可点击文档：用户协议、隐私政策、免责声明，均显示版本。
- 单个明确复选框：“我已阅读并同意上述文件”。
- 主按钮“同意并发起诊断”；次操作“暂不发起”。

### 12.2 强制时序

```text
open → checked=false
未勾选确认 → 留在弹窗并提示
关闭/暂不发起 → 回原页；无 wx.login；无诊断
勾选并确认 → login_pending → session_ready → assessment_creating → progress
```

- 登录中和创建中需要区分提示，避免重复点击。
- 登录失败：提示“登录未完成，尚未创建诊断”，可重试或关闭。
- 诊断创建失败：若 Session 已创建可保留 Session，但清楚说明诊断未创建；幂等重试。
- 报告 Tab 的登录弹窗由用户主动点击触发，不复用诊断协议为报告访问强制同意。

## 13. 诊断进度

### 13.1 阶段

1. 准备企业数据。
2. 检查数据完整性。
3. 执行高企规则。
4. 执行科技型中小企业规则。
5. 执行专精特新规则。
6. 执行杭州新雏鹰规则。
7. 整理证据与行动。
8. 生成报告。

### 13.2 布局与交互

- 顶部显示企业与诊断 ID 的短格式。
- 状态图标 + 当前阶段 + 已完成阶段列表；不显示虚假精确百分比，可按 8 阶段显示近似进度。
- `pending` 显示排队准备；`processing` 显示当前阶段；`ready` 显示查看报告；`failed` 显示友好原因和重新发起。
- `onShow` 立即刷新；前台轮询采用渐进间隔；切后台停止，回前台恢复。
- 离开页面不取消服务端诊断。

## 14. 诊断报告

### 14.1 信息层级

1. 报告标题、企业、生成时间、规则核验日期、Demo 标签。
2. 强免责声明。
3. 四类摘要卡，显示状态、摘要、`manual_review` 数量、主要 gap。
4. 当前选择的资质详情：关键条件预览、规则版本、适用地域、数据完整度。
5. 入口：查看完整证据、查看缺口与行动、联系顾问。

### 14.2 规则

- 报告页不得重新计算比例或状态，只显示服务端 Report 快照。
- `manual_review` 用“需人工核验”，不可与“已满足”同色同文案。
- `not_applicable` 说明具体原因，例如“杭州区域政策，本企业注册地不在杭州”。
- 政策链接跳转前说明为外部政府来源；不暗示本产品代表主管部门。

## 15. 证据链

- 按资质分组；默认展开关键失败/缺失/人工核验项。
- 单项顺序：条件 → 政策要求 → 企业实际数据 → 单位/期间 → 来源 → 判断 → 解释 → 建议行动。
- `actualValue` 缺失显示“未提供”，不能显示 `0`。
- 派生值同时展示原始分子/分母与公式。
- 来源冲突显示全部来源及各自观察时间。

## 16. 缺口与行动

- 筛选：全部 / 高优先 / 需补数据 / 需人工核验。
- Gap 卡：标题、为什么重要、关联规则、影响资质、优先级、证据引用。
- Action 卡：建议动作、建议材料、先后顺序、是否建议顾问、非承诺说明。
- 无明确缺口时仍显示“未发现可自动识别的明确缺口；定性条件及主管部门审核仍需核验”。

## 17. 报告 Tab 五态

| 状态 | 内容 | 主行动 |
| --- | --- | --- |
| 未登录 | 解释登录只为查看保存报告，不自动授权 | “登录查看报告”（点击后才 `wx.login`） |
| 无报告 | 说明尚未发起诊断 | “开始预评估” |
| 诊断进行中 | 企业、创建时间、阶段 | “查看进度” |
| 已完成 | 报告卡列表、四类摘要、生成时间 | “查看报告” |
| 失败 | 企业、失败时间、可理解原因 | “重新发起”/“查看详情” |

进入 Tab 只读取本地 Session 状态；没有 Session 时不得自动登录。

## 18. 我的 Tab 与法律页

- 游客始终看到：使用说明、隐私政策、用户协议、免责声明。
- 已登录额外显示 Demo Session 状态和“退出登录”。
- 退出需二次确认；成功后删除本地 token、敏感草稿并刷新报告 Tab 状态。
- 法律页展示标题、版本、生效日期、正文；协议弹窗应能准确打开对应版本。

## 19. 联系顾问

### 19.1 字段

- 联系人：2–30 字符。
- 手机号：中国大陆 11 位手机号（Demo 校验口径）；不自动读取通讯录。
- 企业：由当前企业带入，可在无企业上下文时手填。
- 咨询方向：四类资质多选或“综合咨询”。
- 备注：可选，最多 500 字符。
- 独立复选框：同意为本次咨询目的处理并联系；默认 `false`。

### 19.2 交互

- 不强制登录、不强制微信手机号授权。
- 提交中禁用重复点击并使用幂等键。
- 成功页只显示“咨询需求已提交”和返回操作，不显示“已接单”。
- 校验失败不清空合法字段；网络失败说明未提交成功。

## 20. Admin 设计边界

- 页面顶部固定“本地 Demo 管理页，不具备生产权限安全”。
- 两个只读区：诊断记录、顾问线索。
- 诊断列：企业、诊断 ID、状态、创建时间、报告状态。
- 线索列：企业、联系人、脱敏手机号（默认）、咨询方向、提交时间。
- 支持 Loading / Empty / Error / Success；不做编辑、导出、派单或角色权限。

## 21. 用户反馈、可访问性与适配

- 触控目标建议不小于 44px；关键按钮保持足够间距。
- 输入控件有可见 label、错误说明和单位，不只依赖 placeholder。
- 长政策名称/企业名支持换行；窄屏不水平滚动核心内容。
- 使用系统字体，正文不小于易读尺寸；颜色对比满足基本可读性。
- 网络请求按钮明确 pending 状态；成功/失败除 toast 外必须有页面级反馈。
- 微信开发者工具验证至少覆盖常见窄屏、标准屏、前后台切换、键盘遮挡和长文本。

## 22. 人工视觉验收清单（Phase 5/6 执行）

- 首次启动无登录、授权、协议弹窗。
- 三 Tab 与普通页导航/返回正确。
- 所有页面四态可见且按钮可恢复。
- 协议首次及重开均未勾选；拒绝不登录。
- 动态表单只出现缺失项，`0`/`false` 正确展示。
