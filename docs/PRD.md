# 企业政府资质预评估微信小程序 Demo｜产品需求文档

> 文档版本：v2.0  
> 规格日期：2026-08-11  
> 政策核验日期：2026-08-10  
> 产品性质：产品验证 Demo，仅提供约 1 分钟的资质准备度预评估，不构成主管部门认定、申报意见或补贴承诺。

## 1. 项目背景

企业准备高新技术企业、科技型中小企业、专精特新中小企业及地方科技企业培育项目时，常遇到政策口径分散、公开信息不完整、材料准备顺序不清和结果难解释等问题。

本产品先使用虚构的企业公开画像，再按实际缺口让用户补充经营数据，输出四类资质的预评估、判断依据、缺口和行动建议，并提供顾问咨询入口。

## 2. 产品目标

1. 游客无需登录即可完成企业搜索、主体确认、画像查看和经营数据补充。
2. 用户在约 1 分钟内完成一次企业资质准备度诊断。
3. 动态表单只询问当前判断真正缺少的数据。
4. 一份报告同时覆盖四类资质，并解释条件、企业数据、数据来源、判断和建议。
5. 无法可靠自动判断的条件明确标记为缺少数据或需人工核验。
6. 用户可在了解结果后自主提交一对一顾问咨询。

## 3. 用户与核心场景

| 用户          | 核心需求                   |
| ----------- | ---------------------- |
| 企业经营者、申报负责人 | 快速了解企业申报准备度和主要缺口       |
| 财务、研发人员     | 明确需要补充的数据口径和材料         |
| 顾问意向用户      | 提交咨询需求，获得后续申报服务        |
| Demo 评审人员   | 在本地复现完整流程并检查产品、架构和测试质量 |

核心场景：用户已有目标企业，希望先低成本判断四类资质是否存在申报机会，再决定是否整理材料或咨询顾问。

## 4. 产品原则

- 先体验后登录：登录不作为浏览前置条件。
- 先使用已有数据：不在入口展示大而全的固定表单。
- 只补关键缺口：动态字段由当前企业数据和规则共同决定。
- 结论可解释：报告说明为什么得出当前判断。
- 不确定性可见：缺失、冲突、人工核验和地域不适用均单独表达。
- 不承诺结果：所有结论均为预评估，以主管部门文件和审核为准。

## 5. 产品范围

### 5.1 Demo 范围

- 原生微信小程序：首页、报告、我的三个 Tab。
- 企业搜索、主体确认、企业画像和动态补充经营数据。
- 协议确认、Demo 登录、诊断进度和报告保存。
- 高新技术企业、科技型中小企业、专精特新、雏鹰企业四类预评估。
- 可解释报告、证据链、缺口与行动清单。
- 游客顾问咨询提交。
- 虚构 Mock 企业、轻量后端和本地数据存储。

### 5.2 非范围

- 官方申报、审批、证书或补贴发放。
- 企查查网页爬取、完整企业数据库或政府系统直连。
- 正式支付、CRM、顾问派单、短信和运营后台。
- 生产级账号、权限、数据库、监控和安全体系。
- 对审计口径、平台评分、专家判断或材料真实性作官方结论。

## 7. 用户主流程

```text
首页
→ 企业搜索
→ 主体确认
→ 企业画像
→ 补充经营数据（存在缺失项时）
→ 发起诊断
→ 阅读并同意协议
→ 建立 Demo 登录会话
→ 诊断进度
→ 诊断报告
→ 证据链 / 缺口与行动
→ 联系顾问
```

用户关闭协议、拒绝协议或登录失败时，不创建诊断，并可继续使用游客功能。

## 8. 首页与三 Tab

### 8.1 首页

- 展示“约 1 分钟了解企业申报准备度”的核心价值。
- 展示四类资质名称、简要说明和雏鹰企业的地域提示。
- 主按钮“开始预评估”直接进入企业搜索。
- 明示本工具不是官方认定，不承诺资质或补贴结果。
- 进入首页时不登录、不弹协议、不请求手机号授权。

### 8.2 报告 Tab

报告 Tab 支持以下状态：

| 状态  | 展示要求                        |
| --- | --------------------------- |
| 未登录 | 说明登录用途，提供“登录查看报告”按钮，不自动调用登录 |
| 无报告 | 提示尚无诊断，提供开始预评估入口            |
| 进行中 | 展示企业、创建时间和当前处理信息，可进入进度页     |
| 已完成 | 展示四类结果摘要，可进入报告详情            |
| 失败  | 展示可理解的失败信息和重新发起入口           |

### 8.3 我的 Tab

- 游客可查看使用说明、隐私政策、用户协议和免责声明。
- 已登录用户额外看到退出登录。
- 退出登录后清除本地会话和经营数据草稿，不删除已保存在后端的历史报告。

## 9. 企业搜索与主体确认

- 搜索关键词去除首尾空格后为 2 至 50 个字符。
- Demo 只返回虚构企业，名称、主体编号和页面均显示“虚构 Demo 数据”。
- 无匹配企业时展示空状态，不伪造真实企业。
- 搜索结果展示企业名称、Demo 编号、地区、行业和经营状态。
- 主体确认页展示企业名称、Demo 编号、法定代表人、成立日期、注册资本、地区、状态和行业。
- 用户可确认该企业，也可返回重新搜索。
- 切换企业时，不得将上一家企业的补充数据用于新企业。

## 10. 企业画像

- 展示系统当前掌握的企业信息，并区分已获取、缺失、待补充和需人工核验。
- 影响判断的字段显示数值、单位、统计期和来源。
- `0` 和“否”是有效值，不得显示为缺失。
- Mock 数据、用户补充和系统推导使用不同来源标识。
- 有缺失字段时进入动态补充页；无缺失字段时可直接发起诊断。

## 11. 动态补充经营数据

动态表单由“四类规则需要的字段”减去“企业画像中已有且口径有效的字段”生成，只展示当前判断缺少的数据。

可能出现的字段包括：

- 企业人数、研发人员和科技人员。
- 营业收入、销售收入、主营业务收入和高新技术收入。
- 研发费用、境内研发费用和资产数据。
- 知识产权、研发成果、企业资质和平台评分。
- 市场、融资、人才和风险声明。

产品规则：

- 字段显示单位、统计期、用途、填写口径和敏感提示。
- 用户补充后重新计算缺失项，表单应真实减少并影响后续报告。
- 用户数据与已有数据冲突时保留冲突并提示人工核验，不静默覆盖。
- 草稿按企业隔离并短期保存；诊断创建成功、退出或过期后清理。
- 用户仍可在关键字段缺失时发起诊断，报告对应显示“需补充数据”。

## 12. 协议、登录与隐私

### 12.1 游客边界

游客可访问首页、企业搜索、主体确认、企业画像、补充经营数据、联系顾问、使用说明、隐私政策、用户协议和免责声明。

首次进入、页面加载和 Tab 切换均不得自动调用登录、手机号或用户资料授权。

### 12.2 发起诊断

1. 用户点击“发起诊断”后打开协议弹窗。
2. 弹窗展示用户协议、隐私政策、免责声明及版本。
3. 协议复选框每次打开均默认未勾选。
4. 用户未勾选、关闭或选择暂不发起时，不登录、不创建诊断。
5. 用户明确勾选并确认后，才调用微信登录并建立 Demo 会话。
6. 会话建立成功后提交协议记录和诊断数据。

报告 Tab 的“登录查看报告”使用同样的协议确认顺序。已有有效会话时可直接查看本人报告，不重复登录。

### 12.3 顾问隐私

联系顾问不强制登录。手机号和咨询内容使用独立隐私告知与复选框，默认未勾选，不复用诊断协议，不强制微信手机号授权。

## 13. 诊断流程

- 创建诊断后先显示等待处理，再显示规则评估进度，最终进入完成或失败。
- 处理中依次展示：准备企业数据、检查完整性、执行四类规则、整理证据与行动、生成报告。
- 诊断进度来自后端状态，不使用固定页面假装加载。
- 页面离开或小程序切后台不取消诊断；回到前台后重新获取最新状态。
- 失败时展示安全、可理解的错误信息，不展示内部堆栈。

## 14. 诊断报告

一份报告必须包含四类资质结果：高新技术企业、科技型中小企业、专精特新、雏鹰企业。

资质汇总状态：

| 状态    | 产品含义                     |
| ----- | ------------------------ |
| 较有希望  | 可自动预筛项未发现重大缺口，仍以主管部门审核为准 |
| 存在机会  | 数值条件有一定基础，仍有材料、平台或人工核验项  |
| 需补充数据 | 关键数据缺失或口径无效，暂时无法完整判断     |
| 暂不满足  | 已有有效数据显示至少一个关键预筛门槛未达到    |
| 不适用   | 地域、主体或规则日期不在当前规则适用范围     |

报告展示企业、生成时间、规则版本、四类摘要、主要缺口和免责声明。禁止使用“保证通过”“一定符合”“已获得资质”“官方认定通过”“保证获得补贴”等表达。

## 15. 证据链

每个判断项至少包含：

- 判断条件和政策要求。
- 企业当前数据、单位和统计期。
- 数据来源及观察时间。
- 判断结果：已达到、未达到、缺少数据、需人工核验或不适用。
- 得出判断的说明。
- 缺失信息和建议行动。

派生比例应能追溯分子、分母和计算口径。缺失值显示“未提供”，不得显示为 `0`。

## 16. 缺口与行动清单

- 针对未达到、缺少数据、数据冲突和需人工核验生成缺口。
- 每个缺口说明为什么重要、影响哪类资质和优先级。
- 每项行动说明建议动作、建议准备的材料和负责人建议。
- 未发现明确缺口时，仍提示定性条件和主管部门审核需要人工复核。
- 行动建议只用于材料准备，不构成申报通过承诺。

## 17. 联系顾问

- 字段：联系人、手机号、企业、咨询方向、备注和独立隐私同意。
- 咨询方向支持四类资质多选或综合咨询。
- 手机号由用户手填，不自动读取通讯录，不强制微信授权。
- 未同意咨询隐私告知时不提交。
- 提交成功显示“咨询需求已提交”，不显示“顾问已接单”。

## 18. 四类资质预评估规则

### 18.1 结果语义

单项条件使用以下产品语义：

| 结果    | 含义                         |
| ----- | -------------------------- |
| 已达到   | 数据口径有效且达到 Demo 预筛条件，仍非官方认定 |
| 未达到   | 数据口径有效且未达到预筛门槛             |
| 缺少数据  | 数据缺失、冲突、期间无效或无法获得          |
| 需人工核验 | 即使有数据，也需审计、平台、材料或专家判断      |
| 不适用   | 地域、主体或规则版本明确不适用            |

### 18.2 政策基线

| 资质      | 规则版本与适用范围                                     | Demo 自动化边界                                   |
| ------- | --------------------------------------------- | -------------------------------------------- |
| 高新技术企业  | 国科发火〔2016〕32号、国科发火〔2016〕195号；中国境内居民企业         | 企业年限、人员和研发比例等可预筛；领域、知识产权核心作用、综合评分和材料真实性需人工核验 |
| 科技型中小企业 | 国科发政〔2017〕115号、国科火字〔2022〕67号及 2026 年通知；全国年度评价 | 规模和部分评分可预筛；会计税务口径、行业、信用和材料真实性需人工核验           |
| 专精特新    | 工信部企业〔2026〕2号，自 2026-04-01 实施；全国、省级认定         | 年限、收入、研发投入等可预筛；市场地位、平台质量评价和省级材料需人工核验         |
| 雏鹰企业    | 杭科高〔2024〕50号，有效至 2027-12-31；杭州“新雏鹰”区域示例       | 非杭州企业直接显示不适用；产业方向、融资、人才、研发和综合评审需按材料核验        |

### 18.3 关键判断项

| 资质      | 关键预评估内容                                                 |
| ------- | ------------------------------------------------------- |
| 高新技术企业  | 注册年限、知识产权、技术领域、科技人员比例、近三年研发费用比例、境内研发比例、高新收入比例、创新能力、重大风险 |
| 科技型中小企业 | 主体与会计税务条件、人数和收入资产规模、行业限制、信用风险、科技人员、研发投入、科技成果、年度评价窗口     |
| 专精特新    | 主体与信用、创新型中小企业基础、专业化年限、主营收入、研发投入、知识产权、细分市场地位、平台评价及过渡条款   |
| 雏鹰企业    | 杭州地域、企业年限、重点产业方向、研发人员或费用、融资人才成果路径、信用风险和综合评审             |

政策只在标注版本和核验时点有效。申报前应重新核对目标年度通知、地方细则和过渡条款。

## 19. 异常与边界情况

| 场景             | 产品处理                    |
| -------------- | ----------------------- |
| 搜索无结果          | 展示空状态并允许修改关键词           |
| 企业详情不可用        | 展示错误和返回搜索入口             |
| 动态字段加载失败       | 保留已有草稿，允许重试             |
| 输入类型、期间或字段关系错误 | 在对应字段提示，不清空其他合法输入       |
| 协议未同意          | 不登录、不创建诊断，允许继续浏览        |
| 登录失败           | 提示登录未完成，诊断尚未创建          |
| 诊断创建失败         | 保留可重试数据，不重复创建           |
| 诊断处理失败         | 报告列表显示失败状态，不生成空报告       |
| 会话过期           | 清除本地会话，回到未登录引导          |
| 报告尚未完成         | 引导查看进度，不展示不完整报告         |
| 顾问提交失败         | 保留表单，说明未提交成功并允许重试       |
| 网络异常           | 展示用户可理解的错误和请求编号，不显示内部堆栈 |

## 20. 验收标准

- 微信小程序可打开，后端可本地启动，Mock 企业搜索可用。
- 首页、报告、我的三个 Tab 及所有主流程页面可访问。
- 冷启动和游客浏览不自动登录、不弹授权。
- 企业搜索、主体确认、画像和动态补数真实可操作。
- 动态补充数据会改变缺失项和诊断结果。
- 协议每次打开默认未勾选；拒绝或关闭后仍可游客浏览。
- 用户明确同意后才建立会话并创建诊断。
- 诊断存在等待、处理、完成和失败状态，完成后生成四类结果。
- 报告可进入证据链和缺口行动页，并显示来源、规则版本和免责声明。
- 报告 Tab 支持未登录、无报告、进行中、完成和失败。
- 联系顾问免登录，独立同意后可真实提交。
- Mock 企业明确为虚构数据，仓库不包含真实密钥。
- README 能指导首次接触项目的评审独立启动并演示。
- 自动测试和人工测试结果如实记录在 `docs/test-cases.md`。

## 21. 已知限制

- 当前只实现 Mock 企业数据，未接入真实企查查 API。
- Demo 登录不等同生产微信身份认证。
- 本地 JSON 数据只适合单进程、低并发演示。
- 部分政策条件只能给出人工核验建议。
- 政策核验时点为 2026-08-10，后续政策变化需更新规则。
- 真机 HTTPS、弱网、多尺寸与键盘、前后台恢复专项尚未人工执行，不影响本地 Demo 主流程结论。
